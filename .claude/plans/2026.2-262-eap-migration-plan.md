## Task 4 — Internal-API: drop redundant `PluginManagerCore` call [§6a]

`PluginManagerCore.getPlugin(...)` is `@ApiStatus.Internal` in 262. GBrowser's only use is the
**redundant** variant AZD called out: an `ErrorReportSubmitter` already inherits a public
`pluginDescriptor` (`PluginDescriptor.getVersion`), so the lookup is pure overhead.

File: `src/main/kotlin/com/github/gbrowser/reports/GBrowserPluginErrorReportSubmitter.kt`

```diff
-import com.intellij.ide.plugins.PluginManagerCore
 …
   private fun StringBuilder.appendRuntimeInformation() {
-    val descriptor = PluginManagerCore.getPlugin(pluginDescriptor.pluginId)!!
     appendEncoded("- **OS:** ${OS.CURRENT}\n")
-    appendEncoded("- **Plugin Version:** ${descriptor.version}\n")
+    appendEncoded("- **Plugin Version:** ${pluginDescriptor.version}\n")
     appendEncoded("- **IDE:** ${ApplicationInfo.getInstance().fullApplicationName}\n")
     appendEncoded("- **IDE Version:** ${ApplicationInfo.getInstance().build.asString()}")
   }
```

This both removes the internal-API usage and deletes a redundant non-null assertion (`!!`).

> **Task 4 is optional/cosmetic for THIS repo — it cannot break or gate the build.** GBrowser's
> `pluginVerification.failureLevel` (`build.gradle.kts:169-174`) was deliberately relaxed (commit
> `5b0a53f`) to gate on **only** `COMPATIBILITY_PROBLEMS` + `OVERRIDE_ONLY_API_USAGES` —
> `INTERNAL_API_USAGES` is **not** a failure level here. So `verifyPlugin` passes whether or not we
> make this change. We do it anyway because the cleaner code is strictly better and trivial, but a
> subagent must not treat it as a build gate, and bumping to 262 (which annotates more APIs internal)
> will **not** surface new `verifyPlugin` failures for the same reason.

## Task 6 — Watch item: VCS `.impl` transitive leak [§2 transitive]

GBrowser's main code references `com.intellij.util.ui.InlineIconButton`
(`GBrowserToolWindowActionBar.kt`), which lives in `intellij.platform.vcs.impl` and currently
arrives transitively via `Git4Idea`. AZD only had to declare these explicitly **because** it added a
content module (a second resolution participant). **GBrowser adds no content module**, so the leak
should remain intact.

- **Do not** pre-emptively add `bundledModule(...)` lines.
- **If and only if** `compileKotlin` fails with unresolved `InlineIconButton` / `com.intellij.vcs.*`
  / `git4idea.*`, add to `build.gradle.kts` `intellijPlatform { }`:
  ```kotlin
  bundledModule("intellij.platform.vcs.impl")   // InlineIconButton
  ```
  (and only the additional `.impl` modules the compiler actually demands — don't over-declare).

## Verification gauntlet (run in order; per CLAUDE.md always `--no-scan`, never `runIde`/`ui-test`)

**Sequencing for subagent-driven execution:** Tasks 1 & 2 are **already applied** (verify only, do
not re-edit). Remaining edits — Task 3 (3a+3b together), Task 4, Task 5, Task 7 — touch independent
files and may run in **parallel**. The gauntlet below runs **serially after all edits** — do not
parallelize it or run it mid-edit. **Task 6 is conditional**: apply it *only if* `compileKotlin`
fails on `InlineIconButton` — never speculatively.

```bash
./gradlew compileKotlin --no-scan          # main compiles against 262 (catches §6a + §2 leak)
./gradlew compileTestKotlin --no-scan      # unit tests compile
./gradlew compileUiTestKotlin --no-scan    # UI tests compile (catches §3 — the IdeaUltimate import)
./gradlew test --no-scan                   # unit tests pass
./gradlew buildPlugin --no-scan            # produces the .zip against 262
./gradlew verifyPlugin --no-scan           # expect "Compatible." — gates COMPATIBILITY_PROBLEMS +
                                           #   OVERRIDE_ONLY only; INTERNAL_API is NOT gated here
                                           #   (build.gradle.kts:169-174). May need CI to resolve a
                                           #   262 IDE during EAP — treat a download/no-op as a
                                           #   CI-confirm item, not a hard local failure.
```

UI suite (`uiTest`) is **not** run locally per CLAUDE.md ("Don't run runIde nor ui-test"). §3 only
fully surfaces at runtime, so flag in the PR that the 262 UI run should happen in CI.
